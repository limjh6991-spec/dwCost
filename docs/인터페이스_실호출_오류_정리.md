## A. 실호출 차단 오류 (미해결 — 인프라/네트워크 조치 필요)

### A-1. 네트워크 라우팅 실패 → 연결 타임아웃 (가장 큰 차단 요인)
- **증상**: ERP `172.16.21.32:8801/8800`, MES `172.16.23.30:8888` TCP 접속 전부 실패(❌). 앱에서 호출 시 응답 없음/타임아웃.
- **원인**: 개발 PC의 VPN 스플릿 터널이 **공장망 대역(`172.16.21.x` ERP / `172.16.23.x` MES)을 라우팅하지 않음**. 해당 트래픽이 Wi-Fi 기본 게이트웨이로 빠져 실패.
  - 근거: VPN 경로에 포함된 `172.16.0.208:1433`은 접속 성공(✅) → **VPN 자체는 정상**. 즉 클라이언트가 아니라 **VPN 게이트웨이의 허용 대역** 문제.
  - VPN이 밀어주는 172.16.x 호스트는 5개뿐(`172.16.0.208, .0.41, .2.253, .4.81, .200.203`) — ERP/MES 대역 미포함.
- **조치(택1)**:
  1. **(권장) VN 앱 서버 `10.100.40.242`(데이터센터)에서 실행** — 공장망 내부 라우트 보유 가능성 높음. 먼저 이걸 확인.
  2. **VPN/방화벽에 `172.16.21.0/24`(ERP)·`172.16.23.0/24`(MES) 대역 추가** — 네트워크 담당자.
- **접근 확인 명령(서버에서)**:
  ```bash
  curl -m 15 -X POST http://172.16.23.30:8888/api/v1/wip_inv \
    -H "Content-Type: application/json" \
    -d "{\"factory\":\"DV01\",\"workDate\":\"20260731\",\"matId\":\"716AP\"}"
  ```

### A-2. ERP cert 미보유 → "ERP 인증정보 미설정"
- **증상**: ERP 인터페이스 호출 시 인증정보 미설정 오류. (MES는 cert 불필요하므로 네트워크만 열리면 즉시 검증 가능.)
- **원인**: ERP cert 4종 `certId / certKey / dsnOper / dsnBis` 미확보 (외부 비밀).
- **조치**:
  1. 영림원에서 4개 값 수령.
  2. **서버 환경변수로 주입** — `application.yml`은 이미 플레이스홀더로 외부화됨:
     ```yaml
     iface:
       erp:
         cert-id:  ${IFACE_ERP_CERT_ID:}
         cert-key: ${IFACE_ERP_CERT_KEY:}
         dsn-oper: ${IFACE_ERP_DSN_OPER:}
         dsn-bis:  ${IFACE_ERP_DSN_BIS:}
     ```
     기동 배치(start 스크립트)의 java 실행 앞에 `set IFACE_ERP_CERT_ID=***` … 4개 추가.
  3. 주입 확인: `GET /api/iface/status` → `erp.certConfigured: true` (비밀값 자체는 미노출).
- ⚠️ **cert 값은 소스/깃/문서에 절대 저장 금지. 서버 환경에만 존재.**

## B. 개발/목 테스트 중 발견·해결된 오류 (참고 — 이미 해결)

### B-1. 실행 인자 오버라이드 미적용 → ERP "인증정보 미설정" / MES "Bad authority"
- **증상**: 목 테스트 기동 시 base-url·cert 오버라이드가 안 먹어 위 오류 발생.
- **원인**: `mvnw spring-boot:run -Dspring-boot.run.arguments="a,b,c"` 의 **콤마(,) 구분 인자가 뭉개져** 개별 프로퍼티 오버라이드가 적용되지 않음.
- **해결**: 전용 프로파일 파일 `application-mocktest.yml`(base-url→목서버, 더미 cert)을 두고 `--spring.profiles.active=local,mocktest` 로 기동 → 확실히 적용.
- **적용 지침**: 로컬/목 테스트 시 인자 나열 대신 **프로파일 파일 방식** 사용 권장.

### (참고) 목 테스트 결과 = 코드 정상
실 API 대신 로컬 목 서버(`scripts/if_mock.js`, 포트 8899)로 백엔드→적재 전 구간 검증:
- MES `WIP_SUBUL` → `loaded:2`, ERP `DEPT_COST`/`STOCK_DETAIL` → 각 `loaded:2`.
- ERP 봉투(중첩 ROOT+cert, `$.DataBlock1`)·MES(`$.data.rows`) 파싱, OPENJSON 적재, 건수 반환 모두 정상.
- **실호출과 동일 코드 경로** — 서버에서 base-url을 실주소로, cert만 실값으로 바꾸면 동일 동작.

## C. 런타임 오류 대응표 (실호출 시 참고)
| 증상 | 원인 → 조치 |
|---|---|
| `/api/iface/*` **401** | 미로그인. `/api/**` 인증 필요 → 로그인 토큰으로 호출 |
| **"ERP 인증정보 미설정"** | cert 환경변수 미주입 → A-2, `/status`의 `certConfigured` 확인 |
| **연결 타임아웃**(응답 없음) | 앱 서버가 공장망 미접근 → A-1, 서버에서 curl 확인 |
| **적재 0건** | 조회조건(파라미터) 불일치 or 해당 기간 데이터 없음 → RAW_JSON/응답 확인 |
| 변환 후 값 형식이 기존(한글)과 다름 | 오류 아님 — 설계상 **API 원문(베트남어/영어) 저장**. 한글화는 별도 결정 |

## D. 실호출 재개 절차 (조건 충족 후)
1. **VN 앱 서버(`10.100.40.242`)에서 공장망 접근 확인** — 위 curl (MES). 닿으면 A-1 해소.
2. **MES 먼저 실호출** (cert 불필요): 화면 [API 호출] → `SELECT COUNT(*) FROM DOI_VN_IF_WIP_SUBUL WHERE SITE='VN'`.
3. **ERP는 cert 주입 후** 실호출 → `DOI_VN_IF_DEPT_COST` 등 확인.
4. 적재는 스테이징까지 — **운영 반영은 변환 프로시저 수동 EXEC** (`UP_VN_IF_XFORM_*`, WIP_SUBUL 변환은 미완).

## E. 실호출 전 확정 필요 (코드 측 TODO — 오류는 아님)
1. **ERP DataBlock 파라미터 매핑**: 화면이 현재 `{yyyymm, site}` 전송 → 인터페이스별 정확 조회조건(예: 부서별계정별비용 `AccDateFr/AccDateTo`)으로 확정. (MES `{factory, workDate, matId}`는 정확)
2. **변환 자동화**: [API 호출]은 적재까지만. 운영 반영 변환은 수동 EXEC — 필요 시 [원가 반영] 버튼/트리거.
3. **WIP_SUBUL 변환 미완**: MES 생산수불(mat_id 그레인, PFL 전/후) → `doi_vn_prod_resc`(도우코드 그레인) 재공평가 비즈니스 변환 별도 설계.
