# VN ERP/MES 인터페이스 실호출 준비 체크리스트

> 목적: 네트워크·인증(cert)이 확보되면 **최소 단계로 실호출→적재→(변환)** 이 되도록 사전 정리.
> 범위: VN(DWCMSTEST). 앱은 **dev 프로파일**로 구동(= DWCMSTEST 접속 + `iface:` 설정 보유).

---

## 0. 현재 준비 상태
| 계층 | 상태 | 비고 |
|---|---|---|
| 스테이징 테이블 `DOI_VN_IF_*` 18종 | ✅ | 원본 적재용 |
| 적재 프로시저 `UP_VN_IF_LOAD_*` 18종 | ✅ | JSON→행 (OPENJSON) |
| 백엔드 오케스트레이션 `/api/iface/fetch` | ✅ | 호출→적재 |
| 프론트 [API 호출] 버튼 (6개 화면) | ✅ | VN 전용 |
| 다운스트림 변환 `UP_VN_IF_XFORM_*` | 🔵 5/6 | WIP_SUBUL 미완 |
| 상태 점검 `/api/iface/status` | ✅ | cert 주입 확인용 |
| **실호출** | ⬜ | 네트워크·cert 대기 |

## 1. 사전 조건 2가지

### (A) 네트워크 — 앱 서버가 공장망에 닿아야 함
- ERP: `172.16.21.32:8801`(TEST) / `:8800`(운영)
- MES: `172.16.23.30:8888`
- **개발 PC/일반 VPN에서는 불가**(공장망 172.16.21.x·172.16.23.x 미라우팅 확인됨).
- **VN 앱 서버(`10.100.40.242`, 데이터센터)에서 실행**하거나, VPN/방화벽에 `172.16.21.0/24`·`172.16.23.0/24` 추가 필요.
- 서버에서 접근 확인:
  ```bash
  curl -m 15 -X POST http://172.16.23.30:8888/api/v1/wip_inv -H "Content-Type: application/json" -d "{\"factory\":\"DV01\",\"workDate\":\"20260731\",\"matId\":\"716AP\"}"
  ```

### (B) cert 인증정보 — ERP만 필요 (MES 불필요)
- 영림원에서 수령: `certId`, `certKey`, `dsnOper`, `dsnBis` (외부 비밀 — 코드/커밋에 절대 넣지 않음).
- **MES(생산·재고수불)는 cert 없이 호출 가능** → 네트워크만 열리면 즉시 검증 가능.

## 2. cert 환경변수 주입 (ERP)
`application.yml`은 이미 환경변수 플레이스홀더로 외부화되어 있음:
```yaml
iface:
  erp:
    cert-id:  ${IFACE_ERP_CERT_ID:}
    cert-key: ${IFACE_ERP_CERT_KEY:}
    dsn-oper: ${IFACE_ERP_DSN_OPER:}
    dsn-bis:  ${IFACE_ERP_DSN_BIS:}
```
서버에서 4개 환경변수를 주입한다. **기동 배치(start 스크립트)에 `set` 추가** 또는 **시스템 환경변수** 등록:
```bat
REM start 스크립트의 java 실행 앞에 추가 (값은 실제 cert)
set IFACE_ERP_CERT_ID=***
set IFACE_ERP_CERT_KEY=***
set IFACE_ERP_DSN_OPER=***
set IFACE_ERP_DSN_BIS=***

java -jar dwisCOST-*.jar --spring.profiles.active=dev
```
> ⚠️ cert 값을 소스/깃/문서에 저장 금지. 서버 환경에만 존재해야 함.

## 3. TEST ↔ 운영 전환
`iface.erp.base-url` 포트로 전환:
- TEST: `http://172.16.21.32:8801`
- 운영: `http://172.16.21.32:8800`

MES는 TEST/운영 동일(`http://172.16.23.30:8888`).

## 4. 배포 후 설정 확인 — 상태 엔드포인트
로그인 후 브라우저/클라이언트에서:
```
GET /api/iface/status
```
반환 예:
```json
{
  "erp": { "baseUrl": "http://172.16.21.32:8801", "certConfigured": true },
  "mes": { "baseUrl": "http://172.16.23.30:8888" },
  "ready": { "mes": true, "erp": true },
  "endpoints": [ { "key": "DEPT_COST", "source": "ERP", "loadProc": "UP_VN_IF_LOAD_DEPT_COST", "useSelCode": true }, ... ]
}
```
- `certConfigured:false` → cert 환경변수 미주입 (2번 재확인).
- 비밀값은 노출되지 않음(주입 여부만).

## 5. 실호출 순서 (권장)

### 1단계 — MES 먼저 (cert 불필요)
1. 화면: **타시스템 > 생산정보 > MES 수불** (VN 사업장) → **[API 호출]**
2. 성공 토스트에 적재 건수 표시.
3. 적재 확인:
   ```sql
   SELECT COUNT(*) FROM DOI_VN_IF_WIP_SUBUL WHERE SITE='VN';
   SELECT TOP 5 factory, mat_id, work_date FROM DOI_VN_IF_WIP_SUBUL WHERE SITE='VN';
   ```

### 2단계 — ERP (cert 주입 후)
1. 화면 예: **부서별계정별비용** → **[API 호출]**
2. 적재 확인:
   ```sql
   SELECT COUNT(*) FROM DOI_VN_IF_DEPT_COST WHERE SITE='VN';
   ```
3. **원가 반영(변환)** — 적재는 스테이징까지만. 운영 테이블 반영은 변환 프로시저 실행:
   ```sql
   EXEC UP_VN_IF_XFORM_DEPT_COST @yyyymm='202606', @selCode='ACTUAL', @site='VN';
   SELECT COUNT(*) FROM DOI_DEPT_COST WHERE site='VN' AND yyyymm='202606';
   ```

## 7. 알려진 미완/주의 (실호출 전 확정)
1. **ERP DataBlock 파라미터 매핑** — 화면이 현재 `{yyyymm, site}` 전송 → `ErpApiClient`가 그대로 DataBlock1로 감쌈. 인터페이스별 정확한 조회조건 필드(예: 부서별계정별비용 `AccDateFr/AccDateTo`)로 매핑 확정 필요. (MES는 `{factory, workDate, matId}` 정확)
2. **MES 파라미터 확정** — factory(사업장→공장코드), workDate(월↔일자 기준), matId(공백=전체) 규칙.
3. **변환 자동화** — 현재 [API 호출]은 적재까지만. 운영 반영은 변환 프로시저 수동 EXEC. 필요 시 [원가 반영] 버튼/자동 트리거 추가.
4. **WIP_SUBUL 변환 미완** — 재공평가(전/후 PFL·도우코드 집계) 비즈니스 변환은 별도 설계.

## 8. 트러블슈팅
| 증상 | 원인/조치 |
|---|---|
| `/api/iface/*` 401 | 미로그인. 로그인 토큰 필요(`/api/**` 인증) |
| API 호출 실패: "ERP 인증정보 미설정" | cert 환경변수 미주입 → 2번, `/status`의 `certConfigured` 확인 |
| 연결 타임아웃(응답 없음) | 앱 서버가 공장망 미접근 → 1(A), 서버에서 curl 확인 |
| 적재 0건 | 조회조건(파라미터) 불일치 or 해당 기간 데이터 없음. RAW_JSON/응답 확인 |
| 변환 후 값 형식이 기존과 다름 | 설계상 **API 원문(베트남어/영어) 저장**. 한글화는 별도 결정사항 |

---

## 9. 안전성
- 스테이징 적재/변환 모두 **멱등**: 동일 키(`SITE=VN`, `yyyymm`, `sel_code`) 삭제 후 재적재 → 재실행 안전.
- 마감월은 변환 전 마감 상태 확인(마감 시 해제→변환→재마감 원칙).
- cert는 서버 환경변수에만 — 소스/깃 유출 금지.
