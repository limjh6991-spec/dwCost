# VN ERP/MES 인터페이스 테스트 결과

> 작성일: 2026-08-11
> 범위: VN(DWCMSTEST) 인터페이스 수신(적재) 흐름. 화면 [API 호출] → 백엔드 → API → 적재 프로시저 → 스테이징.
> 요약: **실 ERP/MES 연결은 실패**(개발 PC/VPN에서 공장망 미접근 + ERP cert 미보유). **로컬 목(mock) 테스트로 전 구간 정상 동작 검증 완료.**

---

## 1. 테스트 대상 흐름
```
[화면 [API 호출]] → POST /api/iface/fetch → 백엔드 HTTP 클라이언트
   → ERP(영림원, cert+DataBlock1) / MES(미라콤, data.rows) → 응답 JSON
   → 적재 프로시저(OPENJSON) → DOI_VN_IF_* 스테이징 → 적재 건수(loaded) 반환
```

---

## 2. 테스트 A — 실 ERP/MES 연결 (❌ 실패)

### 2.1 대상
| 시스템 | 주소 |
|---|---|
| ERP (영림원 K-System) | `172.16.21.32:8801`(TEST) / `:8800`(운영) |
| MES (미라콤 EMI) | `172.16.23.30:8888` |

### 2.2 결과: 연결 불가
VPN 연결 상태에서 TCP 접속 테스트:

| 대상 | 접근 | 비고 |
|---|---|---|
| `172.16.23.30:8888` (MES API) | ❌ False | 라우트 없음 |
| `172.16.21.32:8801` (ERP API) | ❌ False | 라우트 없음 |
| `172.16.21.32:8800` (ERP API) | ❌ False | 라우트 없음 |
| `172.16.0.208:1433` (MES DB, 참고) | ✅ True | VPN 경로에 포함된 호스트 |

### 2.3 원인: VPN 스플릿 터널이 공장망 대역 미포함
- 개발 PC 대역: `172.17.3.2`(이더넷), `172.30.1.78`(Wi-Fi). VPN 연결 시 `10.212.134.100`(이더넷2, GW `10.212.134.101`) 추가.
- VPN이 밀어주는 라우트: `10.100.40.x`(DB/CMS 서버군) + **특정 172.16.x 호스트 5개**(`172.16.0.208`, `172.16.0.41`, `172.16.2.253`, `172.16.4.81`, `172.16.200.203`) + 일부 공인 대역.
- **ERP 대역 `172.16.21.x`·MES 대역 `172.16.23.x`는 라우팅되지 않음** → 해당 트래픽이 Wi-Fi 기본 게이트웨이로 빠지며 연결 실패.
- `172.16.0.208`(VPN 경로 포함)은 접속되므로 **VPN 자체는 정상**. 즉 클라이언트 문제가 아니라 **VPN 게이트웨이 측 허용 대역** 문제.

### 2.4 추가 제약 (ERP)
- ERP 호출은 **cert 인증정보**(`certId`, `certKey`, `dsnOper`, `dsnBis`) 필요. **미보유**(외부 비밀). MES는 cert 불필요.

### 2.5 결론 / 해소 방안
개발 PC/현재 VPN으로는 실호출 불가. 아래 중 하나가 필요:
1. **데이터센터 호스트(`10.100.40.242`, VN 앱 서버)에서 실행** — 공장망 내부 라우트 보유 가능성 높음. (권장, 우선 확인)
2. **VPN/방화벽에 `172.16.21.0/24`(ERP)·`172.16.23.0/24`(MES) 대역 추가** — 네트워크 담당자.
3. ERP는 위에 더해 **cert 확보 후 서버 환경변수 주입** 필요.

> 서버에서 접근 확인용:
> ```bash
> curl -m 15 -X POST http://172.16.23.30:8888/api/v1/wip_inv -H "Content-Type: application/json" -d "{\"factory\":\"DV01\",\"workDate\":\"20260731\",\"matId\":\"716AP\"}"
> ```

## 3. 테스트 B — 로컬 목(mock) 테스트 (✅ 성공)

실 API가 안 닿으므로, 응답을 흉내내는 로컬 목 서버로 **백엔드→적재 전 구간**을 검증.

### 3.1 구성
- **목 서버**: `scripts/if_mock.js` (포트 8899, 내장 http). 경로로 응답 구분 — MES(`wip_inv`/`fg_inv`)=`{data.rows}`, ERP=`{DataBlock1}`.
- **백엔드**: `local` + 임시 `mocktest` 프로파일. `iface.*.base-url`을 `http://localhost:8899`로, ERP cert는 더미(`test`)로 오버라이드.
- **트리거**: 화면 [API 호출]은 로그인 필요 → 검증을 위해 임시 permitAll 테스트 엔드포인트(`/api/test/iface/fetch`)로 `IfService.fetch` 호출. **검증 후 삭제**.
- DB: DWCMSTEST. 테스트 데이터는 `SEL_CODE='TESTX'` 로 격리 후 삭제.

### 3.2 실행 & 결과
| 인터페이스 | 소스 | 응답 | 목 수신 경로 |
|---|---|---|---|
| WIP_SUBUL | MES | `{status:success, loaded:2}` | `POST /api/v1/wip_inv` |
| DEPT_COST | ERP | `{status:success, loaded:2}` | `POST .../BSSACCCtrCostAmtExeList/...` |
| STOCK_DETAIL | ERP | `{status:success, loaded:2}` | `POST .../BSSESMZStockMonthlyAmt/Query` |

### 3.3 스테이징 적재 확인
- `DOI_VN_IF_WIP_SUBUL` (2건): `factory=DV01, mat_id=716AP/720BP, work_date=20260731, boh_a_wip_before_pfl_50=33958/12000, total_output=450`
- `DOI_VN_IF_DEPT_COST` (2건): `CCtrName=Dowoo Vina, AccNo=6421250/6421220, UMCostTypeName=SG&A, DrAmt=74.00/681.82`
- `DOI_VN_IF_STOCK_DETAIL` (2건): 제네릭 목이라 값은 공란(건수/흐름만 확인)

### 3.4 검증된 사항
- ERP 봉투 구성(중첩 ROOT + cert + `data.ROOT.DataBlock1`) 및 응답 `$.DataBlock1` 파싱 정상.
- MES 단순 요청 및 응답 `$.data.rows` 파싱 정상.
- 적재 프로시저(OPENJSON)로 스테이징 적재, 적재 건수 반환(=화면 토스트 값) 정상.
- **실호출과 동일한 코드 경로** — 실서버에서 base-url을 실주소로, cert만 실값으로 바꾸면 동일 동작.

### 3.5 테스트 중 발견/수정
- **문제**: `mvnw spring-boot:run` 의 `-Dspring-boot.run.arguments="a,b,c"` 콤마 인자가 뭉개져 오버라이드 미적용(ERP "인증정보 미설정", MES "Bad authority").
- **조치**: 전용 프로파일 파일(`application-mocktest.yml`)에 base-url·더미 cert를 두고 `--spring.profiles.active=local,mocktest` 로 기동 → 확실히 적용됨. (사용자 실목테스트 시에도 이 방식 권장)

### 3.6 정리(cleanup)
- 임시 테스트 컨트롤러(`IfTestController.java`)·`application-mocktest.yml` 삭제(커밋 안 됨).
- `SEL_CODE='TESTX'` 스테이징 데이터 삭제. 백엔드·목 서버 종료.
- 유지 산출물: 목 서버(`scripts/if_mock.js`), 버튼 테스트 플래그(mixin `showIfApiButton`).

---

## 4. 결론
- **적재 계층·백엔드·프론트 배선은 정상 동작**함을 목 테스트로 확인(전 구간).
- **실 데이터 검증은 네트워크(공장망 접근) + ERP cert 확보 후** 가능. 개발 PC/현재 VPN에서는 불가.
- 다음 단계: 데이터센터 호스트(`10.100.40.242`)에서 접근 확인 → MES 우선 실호출(불필요 cert) → ERP는 cert 주입 후.

---

## 5. 사용자 재현 방법 (로컬 목 테스트)
1. `node scripts/if_mock.js`
2. `application-mocktest.yml`(base-url→`http://localhost:8899`, 더미 cert) 생성 후 백엔드를 `--spring.profiles.active=local,mocktest` 로 기동
3. 프론트 로그인 → 브라우저 콘솔 `localStorage.setItem('IF_API_TEST','1')` → VN 화면에서 [API 호출]
4. 확인: 토스트 건수 + `SELECT * FROM DOI_VN_IF_* WHERE SITE='VN'`
5. 종료: `localStorage.removeItem('IF_API_TEST')`, 목 서버 종료
